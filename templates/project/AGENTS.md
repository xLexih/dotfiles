# Agent guide

How to work in this project.

## Commands

- Work with `just` recipes. Run `just` to list all commands.
- Run one time in each clone: `just setup`.

## Justfile rules

- Keep each recipe five lines or shorter.
- If a procedure needs more, put it in `script/<name>` and write one recipe line to run it. Look at `script/private` as an example.
- Name commands, functions, scripts and variables noun-verb: object first, action second. This is where names like `docker image build` come from. Where no object exists, keep the bare verb rather than invent one (`deploy`, `setup`).

## Private files

- Git does not store these as plain text: `.env*`, `*.private`, `*.private.*`. Files that end in `.example` are not private.
- Git hooks encrypt the private files when you commit. If only private files changed, run `just private-encrypt` first: git refuses a commit with nothing staged. Never stage, copy or send a private file as plain text.
- Show the state of the private files with `just private-status`.

## Changes

- Change the fewest files and lines that complete the task. Do not reformat files that the task does not touch.
- Keep interfaces simple. Refactor an existing function or parameter before you add a new one.
- Write code that shows its purpose. Put a comment only where the code is not clear, for example a workaround.

## README files

- README.md is the main introduction: what the project is, how to run it, how to build or deploy it. Every deeper topic has its own file under `docs/<topic>.md`; a line in the README points to it. Thus the README stays small: it grows with use, never with explanations.
- Open with a centered block: the title on line 1, one bold sentence that says what the project does, and a badge for each technology that the project is built on. Badge format: `https://img.shields.io/badge/<name>-<version>-<hex>` with `?logo=<name>` when shields.io has the logo.
- Close with a right-aligned block that names the tool that wrote the file:
  ```markdown
  <div align="right">

  Generated by <model name>

  </div>
  ```
- Put in it only what a user must see at a first look. A docs file exists only when it earns its place; do not split without reason.
- End with a short section that links every docs file, one line each.

## Verify

- Run shellcheck on each script you changed: `nix develop --command shellcheck -x script/<name>`.
